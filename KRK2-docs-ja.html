Keyboard Render Kit へようこそ！

Keyboard Render Kit 2 へようこそ。ご支援に感謝します！

KRK2 は KRK1 のオブジェクトデータ置き換えワークフローを引き継ぎつつ、より柔軟で、より独立し、より細かい粒度で扱えるようにしました。キーキャップの高さ（プロファイル）は他のモデルのジオメトリに依存しなくなり、キーボードは自由に移植でき、各コンポーネントはバージョンから独立して個別に更新できます。


動作要件

Blender 3.3 以降

Blender Cycles を実行できるコンピューター

関連リンク

Gumroad | BlenderMarket | Instagram | Discord | レジェンドリポジトリ


クイックスタート

パッケージ内容

ダウンロードページでは、blendファイル、txtファイル、レジェンドテンプレート用のSVGなどの素材を含む圧縮ファイルを入手できます。同じフォルダーに解凍して、まとめて配置してください。このtxtファイルはBlenderのアセット管理用サイドカーファイルであり、blendファイルと同じ場所に置く必要があります。


使い始める

KRK2の導入は初代KRKと同じくらい簡単です。Blender（3.3以降）でblendファイルを開くと、必要なものはすべてファイル内に含まれています。開く際に、Blenderがファイルに組み込まれたスクリプトを許可するか無視するかを尋ねてきます。KRK2パネルはこのスクリプトに依存して動作するため、「許可」を選択してください。


ヘルプの入手

コミュニティに参加してください： Discord

関連資料については Blender 公式マニュアル を参照してください。


インターフェース

KRK2 のインターフェースレイアウトは Blender の「シェーディング」（Shading）ワークスペースに最も近く、左カラムがファイルブラウザーと画像エディターからアセットブラウザーと UV エディターに置き換わり、サイドバーに KRK タブが追加されている点が異なります。


アセットブラウザー

アセットブラウザーには多数の実用的なマテリアルが収録されており、種類とメーカー別に分類されています。

Blender マニュアル：アセットブラウザー


UV エディター

このパネルは画像ビューアーとしても、キーキャップ上のレジェンドの座標を表示するためにも使用できます。

Blender マニュアル：UV エディター


3D ビューポート

ここではキット、レイアウト、ライト、カメラアングルなどを編集します。サイドバーにはキーキャップを制御する KRK パネルがあります。

Blender マニュアル：3D ビューポート


シェーダーエディター

ここではマテリアルの外観とプロパティを制御します。

Blender マニュアル：シェーダーエディター


アウトライナー

ここには blend ファイルの階層構造が表示されます。キット、キーボード、レイアウト、アクセサリー、カメラ、ライト、地面、キーキャップの高さ（プロファイル）などがここにあり、それらの可視性も制御できます。

Blender マニュアル：アウトライナー


プロパティ

残りのほとんどのプロパティは各タブに分散しています。

Blender マニュアル：プロパティエディター


KRKパネル

KRKパネルはサイドバー（Nキーで表示）にあり、Relink、Data、Color、Propertiesの4つのエリアに分かれています。最後の2つのエリアは、対応するプロパティが利用可能な場合にのみ表示されます。


Relink（再リンク）

Relinkはオブジェクトデータマネージャーで、キーキャップの高さ（プロファイル）、行、サイズ、キータイプ、ホーミングキーを素早く切り替えるために使用します。チェックボックスにチェックが入っているオプションは、Setを押すとすべて適用されます。


KLEのインポート

KRKはKeyboard Layout EditorのJSONファイルをインポートできます。KLEはオブジェクトに名前を付けないため、インポーターは文字と行（K1-K6）からキーを推測し、推測できる箇所にはプレースホルダーを配置します。このKLEをサンプルとして使用するか、これをベースに独自のレイアウト（配列）を生成できます：

http://www.keyboard-layout-editor.com/#/gists/f7528ebe1348daab7abc45bc2f662c8a


Profile（高さ）

利用可能な高さとそのプレフィックスはアウトライナーのProfileコレクションにあります。行やその他のオプションは何度か使えば感覚がつかめます。オプションを対応する入力欄に入力し（大文字小文字を区別）、チェックボックスにチェックを入れてSetを押すと適用されます。


Row（行）

メーカーやキーキャップの高さによって使用される行番号の体系が異なるため、KRKは独自の番号体系を導入しており、キーボード上の実際の位置を基準に、最後列から数えます。

Size（サイズ）

入力欄に4文字のサイズ単位（unit size）を入力するとキーキャップのサイズを変更できます。対象のジオメトリが存在する限り、キーキャップは指定したサイズになります。


Key（キー）

入力欄にキーキャップ名を入力すると、キーキャップを別のものに交換できます。文字入れ替え可能なキーキャップ（Releg）、無刻印キーキャップ（Blank）、ウィンドウ付きキーキャップ（*_WIN）に交換したいときに特に便利です。


Homing（ホーミングキー）

このドロップダウンメニューでホーミングキーのタイプをバー／ナブ／スクープ（bar/nub/scoop）から切り替え、Setを押します。


Link Material（マテリアルをリンク）

Link Materialは、現在適用されているマテリアルを対象のオブジェクトデータに引き継ぐことができます。有効にするか無効にするかは求める結果によります。例えばプレースホルダーの高さ（PLA）に交換する場合は、Capsmatもプレースホルダーに引き継がれないよう、無効にするべきです。


Copy Settings（設定をコピー）

Setボタンの右側にあるCopy Settingsは、オブジェクトデータ名をオブジェクトデータドロップダウンメニューにコピーし、特定のキーを探しやすくします。


以下のエリアは、現在アクティブ（ハイライト）のオブジェクトに対応するオプションのみを表示します。


Data（データ）

Dataはプロパティパネルのオブジェクトデータとマテリアル割り当てをここに移動し、より簡単にアクセスできるようにします。


ここではオブジェクトデータを素早く検索し、現在のものを別のものに交換できます。例えばキーキャップを複製またはインスタンス化し、そのコピーをスイッチやスタビライザーに変更できます。


キーキャップが複製、インポート、貼り付けによって再リンクできなくなった場合、Restore Meshesを使うとファイル内の同名のバージョンと再接続できます。インポートした方を基準にしたい場合は、そのオブジェクトデータの名前を変更し、末尾の.001を削除してください。


Restore Collectionsはコレクションアセットを選択した場合にのみ表示され、編集可能な状態に復元するために使用します。


ここにあるCopyは、現在アクティブなキーキャップのマテリアルを他の選択中のすべてのキーキャップにリンクし、キーキャップ以外のオブジェクトは無視します。


Color（カラー）

Colorは色とパレットの管理システムで、Capsmat内の色関連のプロパティを制御するのに役立ち、色プロパティが利用可能な場合にのみ表示されます。 選択したキーキャップに色プロパティがない場合はSetupボタンが表示され、そのキーキャップに必要なすべてのプロパティを追加できます。


Custom/Paletteスイッチで、カスタムカラーとパレットの2つのワークフローを切り替えられます。カラーA-EとパレットスライダーA-Eはパレットノードグループを通じて、Capsmatのこれらの部分をオブジェクトごとに制御できます。選択後Setを押すと選択中のすべてのキーキャップに適用されます。各コピーボタンを押せば、一度に1項目だけコピーすることもできます。下部のCopyとPasteは、選択中のすべてのオブジェクトに対してオプションの記録を作成し呼び出すために使用します。


Properties（プロパティ）

Propertiesも同様にカスタムプロパティが利用可能な場合にのみ表示されます。USBケーブルを選択するとケーブルのオプション（編組／TechFlexやコネクタの熱収縮チューブの色など）が表示され、デスクマットを選択するとサイズとステッチのオプションが表示されます。


アセットブラウザー

アクセサリーアセット

アクセサリーは Accessory（アクセサリー）カテゴリにあります。

キーボードアセット

キーボードモデルは Boards（キーボード）カテゴリにあります。

マテリアルアセット

アセットブラウザーには実用的なマテリアルが多数プリセットされており、種類とメーカー別に分類されています。3Dビューポートのオブジェクトに直接ドラッグ&ドロップできます。


マテリアルツール

自分でマテリアルを作る際は、これらのツールをシェーダーエディターにドラッグするとエフェクトを追加できます。


UVエディター

UVエディターは画像ビューアーであり、UV座標エディターでもあります。2D画像が3D空間に文字として貼り付けられたときにどのように見えるかを視覚的に確認できます。


BlenderのUV座標について詳しくは、Blenderマニュアル：UVの説明 を参照してください。


シェーダーエディター

オブジェクトを選択すると、そのオブジェクトに適用されているマテリアルをマテリアルエディターで編集できます。ただし編集内容が反映されるのは、現在アクティブ（ハイライト表示）のオブジェクトだけです。


ドロップダウンメニューから、オブジェクトに別のマテリアルを割り当てられます。


マテリアルを独立させ、編集しても他のオブジェクトに影響しないようにしたい場合は、名前の横にある数字（そのマテリアルを使用しているオブジェクト数）をクリックします。クリックするとマテリアルが複製されます。「新規マテリアル」ボタンを押しても同じ結果になります。


画像テクスチャノードには座標が必要で、これによって 2D 画像を 3D オブジェクトにどのように貼り付けるかが決まります。ベクトル（Vector）入力に何も接続されていない場合は、現在アクティブな UV が使用されます。

一部のマテリアルには、ミュートされたノード（灰色で表示）が含まれており、レンダリング時の計算には含まれません。有効にするには、そのノードを左クリックで選択し、M を押してミュートを解除します。


ワールドマテリアルもマテリアルエディターで編集できます。左上に Object と表示されているドロップダウンメニューをクリックし、World に切り替えます。


アウトライナー

アウトライナーはシーン内のすべての項目を格納し、コレクションとして整理します。

キット

Kits（キット）コレクションはデフォルトで有効になっています。

キーボード

キーボードはまずサイズ別にグループ化され、同じサイズ内ではアルファベット順に並びます。三角矢印をクリックすると子コレクションを階層ごとに展開でき、さらに下には段差CapsLockやTsangan配列の最下段など、キーボードのレイアウトオプションがあります。

レイアウト

これらは予備のレイアウトで、自分でインポートしたキーボードを埋めるのに使えます。レイアウトを右クリックして「リンク複製」を選択するとリンクコレクションが生成されるので、それを自分のキーボードが属するコレクションに移動してください。

アクセサリー

ここにはデスクマットのモデル、マウス、USBケーブル、リストレストなど、利用可能なアクセサリーが一覧表示されます。

シーン

ここではライト、カメラ、背景など、シーンの要素にアクセスできます。

カメラ

KRK2ではカメラを簡素化していますが、複製してカメラ位置やアングルを自分で設定できます。

ライト

シーン全体の印象を決めるためのライトセットアップを複数用意しています。これらは一般的なスタジオ照明のHDRIセットアップを参考にしており、調整の自由度が高く、強度と位置を自由に変更できます。

床

KRKには手軽に始められるよう、興味深い床が一通り付属しています。その中にはシャドウキャッチャー（ShadowCatcher）の床も含まれており、これはFloorLightGreyをベースに、透明背景のレンダリング用に影だけをキャッチするよう特化したものです。

構造

キーキャップの高さ（プロファイル）

すべてのキーキャップの高さ（プロファイル）はここにあります。

UV設定

このコレクションには、キーキャップのUVマップに必要なものがすべて含まれています。

パーツ

ここには追加パーツがいくつか収められており、オブジェクトデータの置き換えで自分のキーボードに追加できます。

プロパティエディター

Blender のプロパティパネルは項目が非常に多いため、ここでは特に関連するいくつかのセクションだけを取り上げます。


レンダープロパティ

レンダーデバイス

GPU（グラフィックカード）を使ってレンダリングを高速化できます。注意：設定で計算デバイスを構成しないと有効になりません。

サンプル数

ビューポートのデフォルトはサンプル数 32、最終レンダリングは 256 です。ポリカーボネート（PC）素材をレンダリングする場合は、最低でも 512 にすることを強くお勧めします。

ノイズ除去

ノイズ除去はここで設定します。私は通常、ビューポートのノイズ除去をオンにして自動に設定し、開始サンプル数を 2 以上にしてビューポートをスムーズに保ちます。最終レンダリングのノイズ除去はコンポジターでも行えます。

フィルム透明

透明な背景の画像をレンダリングするには、Film（フィルム）> Transparent（透明）をオンにする必要があります。

カラーマネジメント

このセクションは重要です。Blender のカラーマネジメントはデフォルトで Filmic になっており、ここでもデフォルトのまま、ルックを適用しません。Standard に設定することを好むユーザーもいます。色合わせがしやすいと感じるからです。私個人は Filmic を好みます。ハイライトの移行がより柔軟で、さらに Medium High Contrast と組み合わせると、見た目は Standard に非常に近くなりながら、明暗の階調がより良くなります。EXR を書き出す予定なら、ここのオプションは関係ありません。EXR は完全なバッファーデータを書き出すからです。

カラーマネジメント

Blender のカラーマネジメントはリニア色空間に基づいており、ビュートランスフォームのデフォルトは AGX（4.0 以前は Filmic）です。これらのビュートランスフォームは非常に広いダイナミックレンジに対応できますが、ポストプロセスを行わない場合、選択した色は灰色がかって見え、コントラストが低くなります。


このワークフローは、ポストプロセスで色をより実物に近い見た目に調整することを前提としています。そうする人は多くない（特に新規ユーザー）ため、KRK 211 以降、KRK はデフォルトで Filmic + Medium High Contrast を採用し、ポストプロセス（コンポジター）で Filmic を sRGB に変換して、より期待に沿った結果を得ています。


ビューポートはすでに設定済みで、表示される内容はすべてコンポジターで処理されます。新しい 3D ビューポートを作成する場合は、コンポジット（compositing）を Always に設定すると、色が正しく再現されます。


最終的な判断は自分の目で行うことを忘れないでください。常に実物の参考と比較しましょう。

マスク

マスクとは、黒地に白文字の画像で、2 つの色や 2 つの要素をどのように混ぜ合わせるかを定義するものです。白が「オン」、黒が「オフ」だと考えるとわかりやすいでしょう。


Capsmat では、マスクを使ってキーキャップのベースカラーと、レジェンド、サブレジェンド、側面レジェンドをそれぞれ混ぜ合わせます。いずれかが欠けている場合、その部分は黒（オフ）として扱われます。


KRK にはテンプレートが付属しているので、これらのマスクを簡単に作成できます。

スイッチとスタビライザーの追加

レンダリングでスイッチやスタビライザーを見せたいことがある。低いアングルから撮影する場合、キーキャップが透明な場合、あるいはキーキャップを隠してキーボード本体だけを見せたい場合などだ。

まずキーボードが含まれるコレクションを展開し、キーキャップ／レイアウトのコレクションを「リンク複製」する。この複製が以降スイッチとして扱われる。


元のキーキャップコレクションの可視性をオフにして、スイッチになる部分だけに集中する。


この複製コレクションを右クリックし、"select objects"（オブジェクトを選択）を選ぶ。そのうち1つがアクティブ（ハイライト）になっていることを確認し、なっていなければ3Dビューポートで Shift を押しながら左クリックしてアクティブにする。次にオブジェクトデータのドロップダウンメニューに "switch" と入力し、必要に応じて Switch_Simple または Switch_Complex を選択する。


これで1つがスイッチになった。Ctrl+L で Link（リンク）メニューを開き、O で Object Data（オブジェクトデータ）を選ぶと、残りのオブジェクトもすべてスイッチになり、キーボード全体のスイッチが揃う。


次にスタビライザーを追加する。スタビライザーが必要なスイッチを1つ選び、Alt+D でリンク複製し、右クリックまたは Esc で移動をキャンセルする。


新しいスイッチを選択したまま、Object Data（オブジェクトデータ）ドロップダウンメニューを開き、"stab" と入力してスタビライザーを絞り込み、必要に応じてシンプルまたは複雑なモデル、およびスタビライザーのサイズと向きを選択する。


残りのスタビライザーも同様に処理すれば完了する。


カスタムキーボードの準備

このチュートリアルでは、使用するCADソフトウェアのエクスポート設定については扱いません。まず設計をOBJまたはFBXとしてエクスポートし、その後Blenderにインポートします。別の方法として、BlenderアドオンのStepperを使ってSTEP/STPファイルを直接インポートすることもできます。


ここでは、Alchemist Keyboards AellaのレンダリングファイルをOBJに変換したものを例として使用します。右クリックして名前を付けて保存


新しいBlenderファイルを作成し、A X Dを押してデフォルトの内容（立方体、カメラ、ライト）を削除し、プロパティパネルのScene Propertiesタブで単位をミリメートル（millimeters）に設定します。


次にAellaのOBJをインポートします：File > Import > Wavefront Obj（F4 I W）をクリックします。


すぐにスケールが正しくないことがわかります。ここではミリメートル単位がメートルとしてインポートされています。


S 0.001を押して、キーボードを1000分の1に縮小します。縮小後は見えなくなる可能性があるので、Homeキーを押してビューを再びフレームに収めます。


次にスケールと回転を適用します：Ctrl+Aを押し、もう一度Aを押して、All Transforms（すべてのトランスフォームを適用）を選択します。


次に移動ハンドルを作成します：Add > Mesh > Plane（Shift+A M P）。


Shiftを押しながらキーボードのボトムケースをクリックして選択に追加し、Object > Transform > Align Objectsで平面を整列させます：ダイアログでShiftを押しながらX軸とY軸の両方をクリックして選択します。


もう一度Align Objectsを繰り返しますが、今回はAlign ModeをNegative Sides（負方向側）に設定し、軸にZを選択します。


平面の位置が正しくなったら、キーボードの底面より少し大きくなるように縮小し（S X、次にS Y）、スケールを適用します。


Object > Convert > Curveでカーブに変換します。移動ハンドルが完成しました。


キーボードのすべてのオブジェクトをこの移動ハンドルにペアレント化します：移動ハンドルを選択したまま、Aを押してすべて選択し、Ctrl+P > Object (Keep Transform)を実行します。これで移動ハンドルを動かすと、他の部分も一緒に動きます。Alt+Gを押して位置をクリアし、移動ハンドルとそのすべての子オブジェクトをワールド原点にリセットします。


次にキーキャップのレイアウトをインポートします。ここでは75%レイアウトを使用します：File > Appendをクリックし、KRK201ファイルを参照してダブルクリックで開きます（blendファイルはフォルダーと同じように動作します）。Collectionsに入り、75を検索して75コレクションを追加します。


そのコレクションのビューポート表示も有効にする必要があるかもしれません：アウトライナーでビューポート無効化フィルター（viewport disable filter）を開き、75コレクションにチェックを入れます。


レイアウトに付属する移動ハンドル（十字形の空オブジェクト）を選択し、メインキーエリア（Alphas）を参照してレイアウトを適切な位置に移動し、X軸で7度回転させます（これがAellaの傾斜角です）。


レイアウトの移動ハンドルをキーボードの移動ハンドルにペアレント化します。


プレースホルダーはキーボードのレイアウトに合わせて1つずつ移動する必要があります。グリッドサイズ（grid size）に0.002381を入力すると、スナップ増分を1/8単位に設定できます。


Tsangan配列の最下段を開きます。


移動するプレースホルダーを選択し、軸拘束を使って移動します：G XでX軸に沿って、G YYでローカルY軸に沿って、といった具合です。Winキーは削除し、Altキーは左側のキーからリンク複製します（Ctrl+Lを押してからO）。Ctrlを押すか、磁石アイコンをクリックしてスナップを有効にすると、スナップ増分を使用できます。


これでキーボードの準備が整い、KRK2にも対応しました。配布用に圧縮blendファイルとして保存し、KRK2にインポートします。


KLE から KRK へ

Keyboard Layout Editor はオブジェクトに名前を付けませんが、Blender と Keyboard Render Kit が正しく動作するには名前が欠かせません。Blender ではオブジェクトとオブジェクトデータが別々に命名されます。Keyboard Render Kit は基本的にオブジェクト名を参照せず、オブジェクトデータ名に大きく依存して動作します。これを押さえておけば、KLE から KRK への変換はかなり確実に行えます。


KRK に変換できるのは何か？ コンバーターが処理するのは、サイズ、レジェンド、行（row）、色（キーキャップの色とレジェンドの色）、位置、回転です。後ろの3つは自由に変更できますが、最初の3つを変更したうえで対応するターゲットのオブジェクトデータが存在しない場合、キーキャップがインポートされないことがあります。


Keyboard Layout Editor の例


このレイアウトは KLE から KRK への変換のテスト基準であり、問題なく KRK に読み込めるため、優れた参考サンプルです。まだ自分のレイアウトを作り始めていないなら、ここから始めるのがおすすめです。どこかで見覚えがあるかもしれません——KRK のキーキャップの UV とテクスチャにはこのレイアウトが使われています。



レジェンドと行の命名に注意してください。変換時に実際に機能するのはこれらであり、変更するとまったく変換できなくなる可能性があります。レジェンド自体は変換されず、キーキャップの名前としてのみ機能することを覚えておいてください——Blender に入った後は、レジェンドマスクを通じて、キーキャップは任意のレジェンドを表示できます。

レンダリングを最適化する

シーンの複雑さ以外にも、レンダリング時間と画質に影響する主な要素がいくつかあります。


解像度

解像度はレンダリング時間に大きな影響を与えます。低すぎると画面にピクセルのブロックが現れ、斜線にジャギーが出て、ディテールに本来あるべきシャープさが失われます。

例：パーセントスライダーを200%に設定すると、解像度は2Kから4Kに倍増し、画質は確かにより精細になりますが、コンピューターが処理するピクセル数は4倍になります。得られる画像はより鮮明になりますが、その代償としてレンダリング時間が大幅に増加します。


レンダリングサンプル数

サンプル数もレンダリング最適化の鍵です。サンプルが少なすぎると画面にノイズが現れます。解像度と同様に、サンプル数を増やすと画質は改善しますが、レンダリング時間は指数関数的に増加します。


ノイズ除去

デジタル画像が生まれた日から、ノイズ除去の需要は存在しました。素材がデジタル写真であれ、スキャンデータであれ、あるいは完全にコンピューターで生成されたものであれ、処理方法は共通です。近年、パストレーシングレンダリングが新しいアルゴリズムの発展を促し、機械学習を使った解決まで始まっています。 Blenderはいくつかのノイズ除去アルゴリズムを提供していますが、ここでは以下の2つに注目します。

Optix

これはNvidiaの機械学習ノイズ除去アルゴリズムで、RTX 20シリーズ以降のNvidiaグラフィックスカードで動作します。専用のテンソルコアを使用するため非常に高速ですが、その代償としてNvidiaユーザーに限定されます。詳細は NVIDIA公式ページ を参照してください。

Open Image Denoise

これはIntelによるもう一つの機械学習ノイズ除去アルゴリズムです。名前が示すとおりオープンソースで、さまざまなCPUモデルとアーキテクチャで動作します。速度はOptixに劣りますが、効果は非常に優れており、透明部分を含むシーン、たとえばポリカーボネート（PC）キーボードのレンダリングでより有利です。Open Image Denoiseの詳細は 公式サイト を参照してください。

実践での使用

どちらのアルゴリズムもオプションで有効にでき、ビューポートと最終レンダリングに使用できます。ただしコンポジターで使用する場合、Open Image Denoiseのほうが高速です。KRKはすでにコンポジターノードを組み立ててあるので、コンポジターパネル左上のチェックボックスで有効にするだけです。


ノイズ除去についてさらに詳しく知りたい場合は、Blenderマニュアル：ノイズを減らす を参照してください。


Poly Havenの素材

キーボードの準備が整い、キーキャップの高さとカラーも決まり、カメラの構図も悪くない。しかし、ライティングと地面がどうしても思った通りにならない。


KRKには地面とライティングのプリセットがいくつか用意されており、そこから始めることもできる。ただ、別の地面やライティングに差し替えて、より豊かな画にしたいこともあるだろう。Poly Havenは優れたリソースサイトで、キーボードを載せる表面も、シーンを照らすHDRI（ハイダイナミックレンジ画像）も揃っている。以下でインポートの流れを説明する。


すでにPoly Havenアドオンをインストールしているなら、この流れのほとんどは省略できる。よく使うなら、インストールを強くおすすめする。


地面

まずPoly Havenのサイト（polyhaven.com）にアクセスし、上部バーのAssets > Texturesをクリックする。


カテゴリがいくつかあるので、ここではFloor > Indoor > Man-Madeをクリックし、Slab Tilesを選ぶ。


ダウンロードボタンをクリックし、zipのダウンロードが終わるのを待って、該当フォルダーに解凍する。フォルダー内にblendファイルがあり、すぐに使えるよう設定済みのオブジェクトが入っていることがわかる。


blendファイルの内容をインポートするには、AppendまたはLinkを使う。ここでは地面をappendし、元ファイルとはリンクしない。BlenderでFile > Appendをクリックし、Poly Havenの地面のインポートを開始する。次にObjectサブカテゴリを選び、地面オブジェクトを見つける。おそらく "Plane" という名前だ。


これはアウトライナー内の現在アクティブなコレクションに追加される。地面がシーンに入ったら、調整に取りかかれる。


デフォルトのジオメトリが少なすぎて、ディスプレイスメントでディテールを押し出せず、テクスチャのスケールもこのシーンでは大きすぎる。Valueノードをスケール（scale）に接続して2に設定し、スケールを2倍に拡大する。自分のカメラアングルでは、マッピングノードでテクスチャを80mm移動させた。さらにモディファイアータブで細分化モディファイアーのレベルを10に変更し、ジオメトリを十分に密にしてディスプレイスメント画像のディテールを支えられるようにする。


ディスプレイスメントを使うなら、地面を少し下に移動させるのも非常に重要だ。これは7mm下げている。地面はこれでレンダリングに使える。


環境

覚えておいてほしい。HDRIはリアリズムを高めるが、色にも影響を与える。キーボードやシーンの撮影なら問題ないが、色の正確さが非常に重要なキットのレンダリングには適さない。HDRIを追加するには、Poly HavenでAssets > HDRIsをクリックし、好きなものをダウンロードする。ここではLeadenhall Marketを使う。ダウンロードするとEXR画像ファイルになる。


アウトライナーでLightsコレクションを無効化する。


次にシェーダーエディターで左上のドロップダウンメニューをクリックし、ObjectからWorldに切り替える。ワールドマテリアルはすでに組まれている。画像ノードを選択してMを押してミュートを解除し、OpenをクリックしてLeadenhall Market画像を読み込む。


この画像を調整したいなら、MappingノードとTexture Coordinateノードを新規作成し、図のように接続する。ここでは画像を52度回転させ、キーボード右側のエッジにきれいなハイライトが出るようにし、同時にHDRIの強度を2倍に上げている。

KRK から 3ds Max へ

3D Studio Max へのエクスポートはそれほど難しくありませんが、事前にいくつか準備が必要です。3ds Max は Blender ほどポリゴン（Nゴン）の扱いが得意ではなく、三角形と四角形を好んで扱います。そのため、Max が扱いやすい形に整えておきましょう。


キーボードまたはキットの準備ができたら、エクスポートに含めたくない他のオブジェクトをすべて非表示にします。通常はシーンコレクションが含まれているので、それをオフにします。


それが表示されている状態で、いずれかのオブジェクトを選択し、A を押してすべて選択し、Tab を押して選択したすべてのオブジェクトをまとめて編集モードに入ります。


面選択モードである必要があります。ショートカットは数字行の 3 です。


A を 2 回押す（または Alt+A を押す）と、すべての選択が解除されます。


次に Select > Select By Trait > Faces By Sides をクリックします。


左下のポップアップパネルでタイプを Greater Than（より大きい）に設定します。


これで、すべての Nゴン（Nゴンのみ）が選択されました。


次に Face > Triangulate Faces をクリックするか、Ctrl+T で三角化し、Tab を押して編集モードを終了します。


これでキーボードをエクスポートできます。File > Export > FBX をクリックし、ファイル名を入力し、Path Mode を Copy に設定し、Limit to Selected Objects（選択したオブジェクトのみ）にチェックを入れるのを忘れないでください。


次に Max でこの FBX をインポートします。


KRK から Cinema 4D へ

Cinema 4D への書き出しは簡単です。

キーボードまたはキットの準備ができたら、書き出したくない他のオブジェクトを非表示にするか、表示をオフにします。


キーボードの A キーを押してすべて選択します。


File > Export > FBX をクリックし、ファイル名を入力して、Limit to Selected Objects（選択したオブジェクトのみ）にチェックを入れるのを忘れないでください。


次に Cinema 4D で FBX をインポートし、Tools > Axis > Reset Scale をクリックして、隣の歯車アイコンでスケールを適用します。


オプションで両方のチェックボックスにチェックを入れます。


よくある質問（FAQ）


Keyboard Render Kit のインストール方法は？

Keyboard Render Kit はすべて blend ファイルにまとめられており、Blender で開くだけで使用できます。


なぜ Blender がスクリプトの実行を求めてくるのですか？

KRK2 には一部アドオン機能があり、登録済みのスクリプトを実行することでインストール不要で動作します。


キーキャップはどこへ行ったのですか？

KRK2 では新しいワークフローを採用しています。シーンにまずプレースホルダーを配置し、KRK パネルで選択したキーキャップの高さ（プロファイル）に置き換えます。


アセットブラウザーが空です。

Blender は、アセットブラウザーに表示する項目とその分類を指定するためのサイドカーファイルを必要とします。圧縮ファイル内の txt ファイルがそれにあたり、blend ファイルと同じフォルダーに配置する必要があります。


キーボードがアセットブラウザーに表示されません。

Blender がコレクションアセットに対応したのは 3.2 からなので、バージョンが Blender 3.2 以上であることを確認してください。


キーキャップにマテリアルがありません。

KRK2 のキーキャップモデルはデフォルトでマテリアルを持ちません。これにより、キーキャップと capsmat をそれぞれ独立して更新できます。

コレクションインスタンスを復元

Restore Collection Instances（コレクションインスタンスを復元）は、Blender の機能の隙間を埋める小さなアドオンです。コレクションアセットは Blender 標準の "Make Instances Real" では正しく復元できません。親子階層は維持されますが、元のコレクション階層は保持されません。


以下は、「階層を保持」オプションを有効にした場合の Make Instances Real と Restore Collection Instances の結果の比較です。

この例では、元のコレクションアセットには 176 個のオブジェクトがあり、その一部は可視性がオフになっています。Make Instances Real では 161 個しか復元されず、さらにすべてのコレクション構造、構成、カラーが失われます。



Restore Collection Instances はもともと Keyboard Render Kit の一部でしたが、汎用ツールとしても使えることがすぐに分かりました。



使い方は簡単です。Ctrl+A を押すと、適用メニューに表示されます。
